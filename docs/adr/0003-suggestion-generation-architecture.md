# 建议生成架构：LLM 措辞、数据定调；画像不出进程；one_liner 确定性

SafePass 的建议层采用「LLM 措辞 + 数据定调」：用户可见的 3–5 条建议正文由 Suggestion Skill 生成，但输出契约强制携带可核对的数据钩子与检索依据（grounds），校验不过即有限重试、仍不过则降级确定性模板；首屏核心结论行（one_liner）永远由确定性模板 + 数据钩子填空，LLM 不写它；六维画像永不离开服务进程（不发送给任何模型供应商），只在本机对建议做排序/加权。

**为什么**：①建议正文是「AI 应用」叙事与场景适配价值的所在，值得 LLM 写；但事实内容必须数据定调，否则安全产品的地基（可核对、可证伪）塌掉。②one_liner 决定「5 秒能否决策」且是页面最显眼的一行，交给 LLM 会把最大注入面与恐慌校验负担压到最关键文本上；Walk Score 式固定人话标签是更好的形态。③画像进 LLM 等于作废隐私页「零上传」的已审计口径（render.py:633），而画像的个性化价值完全可以用本地确定性加权兑现（评级不受画像影响，见 ADR-0002）。

## Considered Options

- **画像打包进 Skill 输入 + 修订隐私页口径**（portfolio 计划补丁 P2 原路径）：个性化最强，但 Trust 支柱倒退，且「晚归女性」等标签一经发送即暴露画像本身。否决。
- **纯确定性模板建议（不接 LLM）**：零注入面、零成本、隐私页一字不改，但「AI 应用」叙事塌掉，作品集轴按计划自身估算封顶约 90。否决——波 1 的目标正是从数据系统走向真 AI 应用。
- **B1 的「关掉 Skill 主指标必须明显变差」DoD**（计划原文）：循环论证，预设 LLM 胜出。否决，改为两路径同台实测对照，数字进 README。

## Consequences

- 隐私页「零上传」口径保持审计过的原样，A1 落地无需改对外承诺。
- 画像差异（A5）用本地确定性加权实现：同一区域不同画像，rating 相等、suggestions 可测不同。
- 建议的每一条事实钩子都可被金标断言（must_mention/must_not_claim），L2 judge 咬合生成物而非模板。
- portfolio-100-execution-plan.md §2 A1/A3/B1 原文与本决议冲突处，以文首补丁 P6（Phase 3 开赛定案）与本 ADR 为准。
