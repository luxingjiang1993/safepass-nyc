## 循环协议（每次迭代照做）

1. 读 `docs/specs/safepass-nyc-mvp-spec.md` 与本文档，找到**第一个未勾选**的任务。
2. **Sensor 准入检查**：核对该任务的每条验收标准都有对应自动化断言（见该任务"先红"测试集）；无 Sensor 的条目不得开工，移出本任务并记入人工验收清单。
3. 若无对应测试集，先按"测试集"章节的定义写出测试（红）。
4. 按 D10 参考代码映射改写参考代码实现该任务（绿）。**不从零写。**
5. 运行全部测试（命令见"运行"章节）。修复失败，重跑。
6. 全部测试绿 → 勾选任务 + 回写文件连接器（勾选状态、测试通过数），进入下一个；最后一个任务绿 → 跑"完成判定"，输出验收报告后停止。

**停止条件**：9 项任务全勾选 + 10 个 pytest 测试集全绿 + 零硬编码审查通过 + 完成判定通过。
**禁止事项**：
- ❌ 不碰 spec / PRD / ADR / CONTEXT.md / 本文件（发现冲突 → 停止并回报，不自行改文档）
- ❌ 不实现 Out of Scope 清单（spec 末节）中的任何内容
- ❌ 不做主观项：建议文案润色、UI 实现、UX 访谈类内容（Ralph 适用性评估表中标 ❌/⚠️ 的条目）
- ❌ 不让 LLM 参与评级计算、不让画像进入评级输入（ADR-0001/0002）
- ❌ 越界判定必须走 spec D12 确定性后置（解析警区 ∉ 覆盖 → 无条件 DegradedResult），不得交由 LLM 路由判断
- ❌ 不把阈值系数（0.7/1.3）、样本量档位、覆盖警区清单写死在代码里——一律读集中配置
- ❌ 不引入 RAG 重排层（MVP 只要 FAISS+BM25+RRF top-3）
- ❌ 不安装 MySQL/PostgreSQL/向量数据库服务等任何需要单独部署的组件（存储形态见 T0 的 spec D11a：版本化文件 / SQLite / FAISS 本地索引）
- ❌ 不用 LLM-as-judge 作为通过判定
- ❌ 不为管线内部子模块另设接缝或 mock 管线内部（唯一接缝 = `execute_query(查询文本, 会话画像, 会话状态) → 结构化响应契约`）

## 运行

```bash
# 测试（全部，循环的判定依据）
pytest tests/ -q
# 性能断言（UX-001 <8s / UX-006 <2s，计时取 P95）
pytest tests/ -q -m perf
```

依赖：`pytest`、`faiss-cpu`、`rank-bm25`、`pydantic`、模型 SDK（参考 `参考代码/RAG-cy` 与 `参考代码/11_实战课` 的 requirements）。模型调用在测试中用可注入的 fake/stub（注入点即接缝的参数），**不发起真实 API 调用的测试必须能在离线环境通过**。

**LLM 行为固定**：凡测试路径经过 FC 路由/LLM 生成（T4、T5 改写句层、T6、T7 三维提取），用**录制回放（cassette）**固定模型响应——录制一次真实调用后离线重放，保证可重复且不进真实 API。LLM 层的真实准确率（路由准确率、FC 兜底召回率）不在本循环判定，移交人工验收清单在线验证。

## 任务清单（按依赖顺序，逐个点绿）

### ☐ T0 数据资产 fixture 三件套（spec D11/D11a，一切红测试的前提）
- **素材清单与下载入口**: `docs/resource-manifest.md` §C（三件套明细、来源、护栏）+ §D（外部数据源链接）+ §G（状态登记）——动手前先查
- **做什么**: 用确定性脚本生成并版本化三份 fixture：①模拟 NYPD 数据集（覆盖评级四档 + 样本量各档：含 <10 ⚪ 案例、10–29 / 30–99 / ≥100 案例、0.7× 与 1.3× 边界附近案例；记录含警区/犯罪类型/时间戳/来源标注字段）②警区安全场所静态表（5 警区各一份 24h 清单 + 通用清单，未核实电话只列机构名）③RAG 知识库文档 15 篇（含华人特定注意事项；未记载项明确写"未记载"）
- **存储形态（D11a，显式排除）**: **不装 MySQL/PostgreSQL/向量数据库服务**。数据集 = 版本化 CSV/JSON 或 SQLite 单文件（二选一）；向量库 = FAISS 本地索引文件 + BM25 pickle（改写 `参考代码/RAG-cy/src/retrieval.py` 落盘模式）；embedding 用本地 sentence-transformers 级模型，不依赖 API
- **来源分层**: 数据集 = 脚本生成（禁 LLM）；安全场所表与知识文档 = **人工搜集/撰写后录入**，执行两条护栏：未核实的信息不编（只列机构名或写"未记载"）；这是内容工作，录入后方可生成索引
- **先红**: fixture 自检集——脚本跑两遍输出逐字节一致（确定性）；数据集用独立复算脚本断言四档评级与各样本量档都有对应案例
- **参考代码**: D10 表"数据 Agent 与评级引擎的验收模式"行（pytest 契约测试组织方式）；检索索引落盘模式见 `RAG-cy/src/retrieval.py`
- **绿灯标准**: fixture 自检通过；T1 需要的聚合输入就绪
- **红线**: 数据生成脚本不得使用 LLM（保证可复现）

### ☐ T1 数据 Agent 聚合
- **做什么**: 对模拟 NYPD 数据集按警区聚合：12 个月 per-100k 犯罪率、样本量（真实命中记录数）、犯罪类型 Top 5、白天/夜间案件量分布
- **先红**: `数据Agent聚合集` — 给定固定模拟数据集，逐警区断言聚合数值精确相等；sample_size 等于真实命中条数（不许出现硬编码数字）
- **参考代码**: D10 表"数据 Agent 与评级引擎的验收模式"行
- **绿灯标准**: 聚合集全绿

### ☐ T2 评级引擎 + 可信度映射（纯函数）
- **做什么**: 输入 T1 统计 + 全市均值 → 输出评级枚举与可信度档。0.7/1.3 阈值与样本量档位（≥100 / 30–99 / 10–29 / <10）读集中配置；<10 强制 ⚪ 且不输出评级与可信度
- **先红**: `评级可复算集` — 独立按阈值规则复算每一警区期望评级，与引擎输出 100% 一致（含 ⚪ 分支）；边界值用例（恰 0.7×、恰 1.3×、恰 10 条、恰 30 条、恰 100 条）
- **参考代码**: D10 表"数据 Agent 与评级引擎的验收模式"行（Host 自算期望比对模式）
- **绿灯标准**: 评级可复算集全绿
- **红线**: 函数签名与实现中不得出现 LLM 客户端、不得出现画像参数

### ☐ T3 降级分支
- **做什么**: 路径查询、趋势查询、越界查询（含"哥大附近"→26 警区）、中城查询（跨 14/18 警区）→ DegradedResult：开发中说明 + 替代信息（所在区域评级/时间模式，若在覆盖内）+ 重新选择邀请；零路径/趋势级结论。**越界判定走 spec D12 确定性后置**：地址解析结果 ∉ 覆盖清单 → 无条件 DegradedResult，此校验在 FC 路由之后、数据查询之前，LLM 误路由也会被强制改写
- **先红**: `降级行为集` — 每类输入断言：type=degraded、degraded_capability 正确、覆盖内时替代信息含真实评级、响应文本不含路径级词汇黑名单（如"路线风险""照明""替代路线"）；含一条"LLM 误路由越界查询"用例，断言后置校验强制改写为 DegradedResult
- **绿灯标准**: 降级行为集全绿

### ☐ T4 FC 路由 + 输出控制管线
- **做什么**: LLM function calling 路由到 `area_safety_query` / `area_comparison` / `follow_up` / `degraded_response` / `emergency_help`；所有 LLM 结构化输出走统一管线：JSON mode 生成 → 解析/修复 → Pydantic 结构 + 业务规则校验 → 有限重试（有上界）→ 明确失败。响应统一为四种契约形态（spec D3）
- **先红**: `输出控制管线集` — 注入损坏 JSON → 有限重试内收敛或抛明确失败；重试次数 ≤ 配置上界；契约非法（如 rating 自由文本）被业务校验拒绝
- **参考代码**: D10 表"FC 路由层"行 + "输出控制管线"行
- **绿灯标准**: 管线集全绿；已有 T1–T3 测试保持绿

### ☐ T5 紧急检测两层 + 静态紧急组装
- **做什么**: 第一层关键词静态表命中即进无 LLM 静态分支；第二层 FC 路由 `emergency_help` 兜底；EmergencyResult 由静态模板 + 警区静态表组装（911 引导、中文报警用语、信息清单、按警区安全场所清单/通用清单、311）；无区域查询时不出"最近"类定位词
- **先红**: `紧急触发集` — 关键词直录 + 改写句合计触发率 > 95%；静态分支 LLM 调用计数 = 0；EmergencyResult < 2s；清单字段与警区静态表逐字段一致
- **参考代码**: D10 表"紧急检测第一层"行
- **绿灯标准**: 紧急触发集全绿

### ☐ T6 追问上下文承接
- **做什么**: 会话状态只存上轮结构化结果（地点/评级/数据摘要）；对比追问走 F3 对比流程、细节追问叠加人群/时间维度；换地点/换话题即重置；追问越界走 F3-5
- **先红**: `追问集` — 对比追问/细节追问承接正确、换地点不复用上轮、追问越界按单边越界规则
- **参考代码**: D10 表"会话状态与追问上下文"行
- **绿灯标准**: 追问集全绿

### ☐ T7 中文地址识别 + NEG 负例防线
- **做什么**: 中文地址映射（含别名："哥大附近"→26 警区、"布鲁克林 Heights"等）；NEG-001~009 负例行为：种族偏见转向结构性解释、武器建议拒绝、无个体隐私信息、无恐慌夸大、免责声明每处存在、评级不变性
- **先红**: `中文地址识别集`（10 地址 10/10，对齐 PRD UX-002）+ `画像不变性集`（同区域有/无画像、不同问法评级一致）+ `负例集`
- **绿灯标准**: 三个集全绿

### ☐ T8 情报 Agent 混合检索 + RAG 知识库
- **做什么**: FAISS 向量 + BM25 关键词双路召回，RRF 融合取 top-3，在 T0 生成的 15 篇知识库文档上检索；产出 `community_info`（仇恨犯罪记录/华人诈骗提醒/中文警员/社区资源），未记载项标注"未核实到"（F7-3 诚实路径）；只列有官方来源的社区资源
- **先红**: `检索集` — 专名查询（精确地名/犯罪术语）+ 语义查询共 ≥10 条，断言对应报告全部出现在 top-3；`community_info` 字段断言：知识库未记载的中文警员项输出"未核实到"、无官方来源机构不出现在资源列表
- **参考代码**: D10 表"情报 Agent 混合检索"行（`RAG-cy/src/retrieval.py` 双路召回模式改写；**不引入**其重排层）
- **绿灯标准**: 检索集全绿；AC-015 覆盖表行闭环
- **注意**: 向量侧用本地 embedding 模型（如 sentence-transformers）保证离线可跑

## 完成判定（全绿后执行并输出报告）

1. `pytest tests/ -q` 全绿（含 perf 标记）。
2. **Sensor 完整性审查**：逐行核对"AC → Sensor 覆盖表"，确认每条 Sensor 在 `tests/` 中有对应实现且通过；确认表中标注"循环外"的条目确实未混入循环产出。
3. grep 审查：代码库无硬编码样本量文案、无散落的 0.7/1.3/警区号字面量（配置文件中除外）。
4. 逐任务核对"红灯"——每个测试集确实是先写好后实现转绿的（报告各任务测试先于实现的证据：文件时间或任务勾选顺序）。
5. 输出验收报告：9 任务勾选状态、10 个 pytest 测试集通过数、Sensor 审查结果、grep 审查结果、遗留风险。
6. 报告中显式声明未做项：主观项（建议文案、UI、UX）与 LLM 层真实准确率（在线验证）不在本循环范围，转标准 Implement / 人工验收。
