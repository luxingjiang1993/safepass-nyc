## Problem Statement

计划或正在纽约生活、学习、工作的中文用户，在做安全相关决策时面临一个结构性困境：小红书经验贴碎片化且互相矛盾，NYPD 官方数据全英文、无分析、难理解，Google Maps 只给最快路线不给安全路线，Citizen 类应用只制造恐慌。他们需要的不是更多数据，而是"能听懂、能信任、能行动"的中文安全情报——这个需求目前没有任何产品真正满足。更关键的是，在紧急时刻（被跟踪、遇到危险），语言障碍会让恐慌加倍，他们不知道用中文该怎么求助、该提供什么信息。

## Solution

SafePass NYC 是一个 AI 安全管家：用户用中文自然语言提问（"上东区晚上安全吗？我是女生"），系统返回结构化、可验证、可行动的安全分析——四级安全评级（🟢🟡🔴⚪，纯数据阈值计算、可复算）、一句话总结、分维度具体情况、3-5 条贴心建议、数据来源与可信度标注、诚实的"我不知道"区域。覆盖 5 个核心警区（19 上东区 / 109 法拉盛 / 5 唐人街 / 90 威廉斯堡 / 84 布鲁克林高地），支持双区对比、两种有限追问、会话级可选用户画像（零持久化），并在检测到紧急输入时以 <2s 进入无 LLM 的红色极简紧急模式（911 中文引导 + 按警区安全场所清单）。对 MVP 不具备的能力（路径级评估、长期趋势、越界区域），系统诚实降级并给出替代信息，绝不编造。

## User Stories

1. 作为第一次来纽约的留学生，我想输入"上东区安全吗？"得到该区域的安全分析，以便做租房决策。
2. 作为留学生，我想输入"我是女生，晚上10点从图书馆回家，Upper East Side安全吗？"，让系统同时理解区域、人群、时间三个维度，以便得到贴合我处境的分析。
3. 作为中文用户，我想系统能识别"上东区""法拉盛""哥大附近"等中文地址，以便不需要英文就能完成查询。
4. 作为用户，我想在结果顶部看到 30 字以内的一句话核心结论，以便 3 秒内抓住要点。
5. 作为用户，我想看到 🟢🟡🔴⚪ 四级评级，以便直观判断区域安全程度。
6. 作为谨慎的用户，我想知道评级的计算依据（该警区 per-100k 犯罪率相对市均值的倍数），以便验证系统没有夸大或压低风险。
7. 作为用户，我想看到分维度的具体情况（白天/夜晚、街道/地铁/公园、女性/学生/老人），以便理解风险的时空分布。
8. 作为用户，我想收到 3-5 条具体可操作的建议（"走 Madison Ave 主干道""随身包放身前"），而不是"注意安全"这种空话，以便真正改变行为。
9. 作为用户，我想看到"🤷 我不知道的"区域明确列出数据缺口，以便知道哪些结论不该被过度信任。
10. 作为用户，我想每处数据都标注来源（模拟数据/真实 NYPD 数据）和覆盖时间范围，以便判断数据底子。
11. 作为用户，我想看到可信度星级（由本次查询命中的样本量档位映射），且样本量数字是动态生成的真实命中数，以便判断结论的统计厚度。
12. 作为用户，我想在分析末尾看到"本分析仅供参考，不替代专业安保建议"的免责声明，以便正确理解产品定位。
13. 作为正在选房的用户，我想问"上东区和布鲁克林 Heights 哪个更安全"并得到双区对比（总体评级、主要犯罪类型、夜间风险、女性安全），以便做出最优选择。
14. 作为用户，当对比的两个区域只有一个在覆盖范围内时，我想系统只对覆盖区出分析、对越界区诚实说明"没有数据，无法公平对比"，并邀请我重新选择，以便不被无依据的对比结论误导。
15. 作为用户，我想对比结果给出"如果你更在意 X 选 A；更在意 Y 选 B"的决策辅助，以便把安全因素融入权衡。
16. 作为带孩子的家长用户，我想在侧边栏填写"有小孩"等画像后，建议层优先呈现学校周边相关内容，以便建议更贴合我的家庭处境。
17. 作为用户，我想明确知道画像只在本次会话生效、关闭页面即删除，以便安心填写而不担心隐私。
18. 作为用户，我想不填画像也能完成全部查询，以便零门槛使用产品。
19. 作为用户，我想在"我是女生"写在查询文本里时，该信息只作用于当次查询，并收到"可固定到侧边栏"的提示，以便控制画像的作用范围。
20. 作为用户，我想同一区域在有画像和无画像时返回完全相同的安全评级，以便信任评级的客观性。
21. 作为晚班族用户，我想画像为"经常加班晚归"时，时间风险提示被个性化前置（"对你来说，22:00 后风险上升"），以便更早看到与我相关的信息。

## Implementation Decisions

### D1. 单一测试接缝：后端 Agent 管线

系统的核心逻辑收敛在一个接缝上：`execute_query(查询文本, 会话画像, 会话状态) → 结构化响应契约`。紧急检测、意图路由、数据聚合、评级计算、降级分支、建议生成全部在该管线内部完成，通过此接缝的函数级/API 级测试覆盖全部验收标准。前端是纯渲染层，消费响应契约，不承载业务逻辑。管线内部子模块之间的交互是普通函数调用，不为子模块单独设接缝。

### D2. 模块划分

| 模块 | 职责 |
|------|------|
| 会话状态（session_state） | 持有会话级用户画像与上一轮结构化查询结果（追问的上下文载体）；画像零持久化、零上传，随页面关闭销毁 |
| 紧急检测层 | 第一层：关键词静态检测，优先于一切 LLM 调用，命中即进静态紧急分支；第二层：FC 路由中的 `emergency_help` 工具兜底（用户用不含关键词的表述描述紧急情况时由路由层接住） |
| FC 路由层 | LLM function calling，将查询路由到声明的工具集合：`area_safety_query`、`area_comparison`、`follow_up`、`degraded_response`（路径/趋势/越界降级共用一个降级工具，由意图细分区分文案） |
| 数据 Agent | 对模拟 NYPD 数据集按警区聚合，产出结构化统计：12 个月 per-100k 犯罪率、样本量（命中记录数）、犯罪类型 Top 5、白天/夜间案件量分布 |
| 评级引擎 | 纯函数：输入数据 Agent 的统计 + 全市均值 → 输出评级与可信度档。零 LLM 参与、零画像参与 |
| 情报 Agent | 混合检索（FAISS 向量 + BM25 关键词，RRF 融合取 top-3）在 15 篇预计算安全报告（含华人特定注意事项）上检索语境材料 |
| 建议生成 Skill | 以 Skill 形式声明（提示词模板 + Pydantic 输入/输出契约 + 业务校验规则）：生成一句话总结、具体情况、贴心建议、诚实缺口清单；画像只作为建议排序与个性化表述的语境输入 |
| 输出控制管线 | 所有 LLM 结构化输出的统一运行时：消费者契约 → JSON mode 生成 → 解析/修复 → 结构 + 业务规则校验 → 有限重试或明确失败 |
| 结构化响应契约 | 管线唯一对外输出，前端消费的唯一数据结构（见 D3） |

### D3. 结构化响应契约（响应字段决策）

管线输出一个判别联合（discriminated union），`type` 字段区分四种响应形态，前端据此渲染：

```
SafetyQueryResult   # 覆盖区内查询：rating(green|yellow|red|insufficient_data)、
                    # rating_explainable_basis(per-100k 与市均值倍数)、confidence_tier(HIGH|MODERATE|LOW|null)、
                    # sample_size(动态真实命中数)、one_liner(≤30字)、dimensions[]、suggestions[]、
                    # unknowns[]、sources[]、time_range、charts(top5_types[]、day_night{day,night})、
                    # community_info(仇恨犯罪/诈骗提醒/中文警员/社区资源，未核实项标注)、
                    # emergency_resources、disclaimer
ComparisonResult    # 双区对比：两区各自 SafetyQueryResult 摘要 + 对比维度表 + 决策辅助话术；
                    # 单边越界时越界侧只有 out_of_coverage 说明，无对比结论
EmergencyResult     # 紧急模式：is_emergency=true、911 引导、中文报警用语、信息准备清单、
                    # 按警区安全场所清单（或通用清单）、安抚话术、311/社区协助电话
DegradedResult      # 诚实降级：degraded_capability(path|trend|out_of_coverage)、
                    # 替代信息（所在区域评级/时间模式，若在覆盖内）、明确的"开发中/无数据"说明、
                    # 重新选择邀请、通用建议与紧急资源
```

所有四种形态共享的横切字段：`disclaimer`（每处分析末尾自动附加）、`sources`、`sample_size`（如有）。评级字段是枚举，不出现自由文本评级。

### D4. 评级规则集中配置（ADR-0001）

评级引擎读取集中配置，不允许散落在代码中：

- 阈值系数：`green < 0.7×` 市均值、`yellow 0.7–1.3×`、`red > 1.3×`
- 样本量门控：`<10` → ⚪ 数据不足，**不给出评级、不给可信度**；`10–29` → LOW ⭐⭐☆☆☆；`30–99` → MODERATE ⭐⭐⭐☆☆；`≥100` → HIGH ⭐⭐⭐⭐⭐
- 可信度档与评级同源（同一 sample_size 输入），每档附固定自然语言解释（非学术术语，如"基于本次查询命中的 N 条记录，数据量适中"）
- 全市均值与覆盖警区清单（19/109/5/90/84）同为配置；中城（跨 14/18 警区）明确不在覆盖清单中

### D5. 画像作用域（ADR-0002）

用户画像（性别、年龄、身份、英语水平、来美时长、场景标签）的作用域严格限定为两处：①时间风险提示的个性化表述与前置；②贴心建议的生成语境与排序。画像不进入评级引擎的任何输入。测试用 NEG-009 保证：同一区域在有无画像、不同问法下评级一致且与阈值规则复算一致。

### D6. 追问的上下文载体

追问（对比追问、细节追问）的上下文载体是上轮查询的**结构化结果**（地点、评级、数据摘要），不是完整对话历史。换地点、换话题即视为新查询，`follow_up` 路由失效，走新查询流程。

### D7. 紧急模式无 LLM

关键词静态检测命中后，紧急响应由静态模板 + 警区静态表直接组装，不经过任何 LLM 调用，保证 <2s。FC 兜底触发的紧急响应同样走静态组装（路由判定后不再生成自由文本）。

### D8. 数据来源分层

MVP 数据集为模拟 NYPD 数据，每个数据点必须携带来源标注（模拟数据/真实 NYPD 数据/混合），响应契约的 `sources` 字段原样透出。RAG 知识库（15 篇预计算安全报告）中的事实（如中文警员信息）只在报告有记载时呈现，否则输出"未核实到"。

### D9. 图表数据边界

两张图（犯罪类型 Top 5、白天 vs 夜间）的数据全部来自数据 Agent 的本次聚合结果，图注沿用 sample_size 动态文案。⚪ 数据不足时整个图表模块在契约中标记隐藏（`charts: null`），前端不渲染空图。

### D11. 数据资产 fixture 三件套（红测试的前提）

以下三份数据资产是测试 fixture，先于一切任务生成，随仓库版本化，由确定性脚本生成（同脚本同参数 → 同数据，保证评级可复算集可跨机器复跑）：

1. **模拟 NYPD 数据集**：逐条记录含警区、犯罪类型、时间戳（含昼夜可判定字段）、来源标注字段；规模必须覆盖评级四档与样本量各档——含至少一个 <10 条的 ⚪ 案例、若干 10–29 / 30–99 / ≥100 档案例，且至少一个警区落在 0.7× 与 1.3× 边界附近（供边界用例）
2. **警区安全场所静态表**：5 个核心警区各一份 24 小时安全场所清单（便利店/医院/警局，含地址电话）+ 通用清单（911/311 + 五警局）；来源必须已核实，未核实电话的机构只列机构名（F7-4 同款规则）
3. **RAG 知识库文档**：15 篇预计算安全报告（含华人特定注意事项、各警区中文服务记载情况）；未记载的事实（如某警区中文警员）在文档中明确"未记载"，供"未核实到"标注路径测试

**D11a. 存储形态决策（显式排除项）**

- **不引入 MySQL/PostgreSQL 等服务型数据库**：MVP 无事务、并发、多表关联需求；如需"真实数据库"叙事，用 **SQLite 单文件**（零安装、拷走即跑、满足 PRD §9.1 数据本地原则）。fixture 默认形态 = 版本化文件（CSV/JSON）或 SQLite，由 T0 实现者二选一，判定标准不变
- **向量库 = FAISS 本地索引文件**（`faiss-cpu`），不引入 Milvus/Qdrant 等向量数据库服务；BM25 索引同为本地文件（pickle，参考 `参考代码/RAG-cy/src/retrieval.py` 的索引落盘模式）；embedding 用本地模型（sentence-transformers 级），不依赖 API
- 三件套的知识来源分层：数据集 = 脚本生成；**安全场所表与知识文档 = 人工搜集/撰写后录入**，录入时必须执行两条护栏（未核实不编、未记载写明"未记载"），这是内容工作不是代码工作

### D12. 越界判定确定性后置（零编造的结构性保证）

地址解析结果是越界判定的唯一权威：解析出警区 ∉ 覆盖清单 → **无条件**产出 DegradedResult，此判定为确定性代码路径，发生在 FC 路由之后、数据查询之前，不受 LLM 路由结果影响。即使 LLM 把越界查询误路由到 `area_safety_query`，后置校验也会强制改写为 DegradedResult。同理，样本量 <10 的 ⚪ 判定也在评级引擎内确定性完成，LLM 无权覆盖。

## Testing Decisions

**什么算好测试**：只通过唯一接缝 `execute_query(查询文本, 会话画像, 会话状态)` 断言输出的**结构化响应契约**——外部可观察行为（评级枚举值、降级标记、is_emergency、sample_size 与数据集真实计数一致、建议条数、unknowns 非空等），不测试内部模块交互、不 mock 管线内部、不测试前端渲染。

**测试资产**（全部以契约断言编写；canonical 口径 = 10 个 pytest 测试集 + 零硬编码 grep 审查 + perf 标记，与 RALPH.md 一致）：

| 测试集 | 覆盖 | 通过标准 |
|--------|------|---------|
| 数据Agent聚合集 | 对固定模拟数据集按警区聚合 | 逐警区数值精确相等；sample_size = 真实命中数（T1） |
| 评级可复算集 | 对覆盖区逐警区用阈值规则独立复算 | 100% 与管线输出一致，含边界值用例（ADR-0001 / AC-004） |
| 降级行为集 | 路径查询、趋势查询、越界查询、中城查询、单边越界对比 | 100% 进入 DegradedResult 形态、零编造（AC-016/019/020、F2-D1~D3、D12 后置校验） |
| 输出控制管线集 | 损坏 JSON 注入、非法契约、重试上界 | 有限重试有界；非法契约被拒；失败明确 |
| 紧急触发集 | 关键词直录 + 不含关键词的改写句 | 两层合计触发率 > 95%，EmergencyResult < 2s（AC-013、UX-006、NEG-008） |
| 追问集 | 对比追问、细节追问、换地点重置、追问越界 | 承接正确 / 重置明确 / 越界走 F3-5（AC-021） |
| 中文地址识别集 | 10 个常见中文地址（含"哥大附近"等映射别名） | 10/10（UX-002）；扩展标注集 > 90%（NEG-007） |
| 画像不变性集 | 同一区域 × 有/无画像 × 不同问法 | 评级字段完全一致（NEG-009 / AC-012） |
| 检索集 | 专名查询 + 语义查询对 15 篇知识库文档的 top-3 命中 | 含对应报告的查询 top-3 全部命中（混合检索 FAISS+BM25+RRF） |
| 负例集 | 种族偏见诱导、武器建议、个体隐私、恐慌性区域、免责声明存在性 | NEG-001~009 全过 |
| 零硬编码审查（grep） | 全库样本量固定文案与阈值散落 | 无固定数字（KPI §8.1）；配置文件除外 |

**LLM 依赖层的验证分层**：紧急 FC 兜底、意图路由的准确率依赖真实模型行为，离线 fake/stub 下测的是 stub 本身。约定：离线测试用**录制回放（cassette）**固定模型行为，保证可重复；LLM 层真实准确率（路由准确率、FC 兜底召回）标注为在线验证项，进人工验收清单，不作 Ralph 通过判定。

**性能测试**：正常查询端到端 < 8s（UX-001），以接缝级计时断言。

**测试先写顺序建议**：评级可复算集与降级行为集是产品信任的基石（ADR-0001、诚实原则），优先于建议文案类测试。

**红绿直连说明（无需另写 TDD 文档）**：每个 Ralph 候选的下表"机器通过标准"即其红灯用例定义——实现前测试集编写完成即为红，管线输出使全部断言转绿即为完成。测试集名称即红绿清单，不另立 TDD 计划文档。
